## 决策列表

### D-001：升级路径采用三段式

- **日期**：2026-09-30
- **决策**：采用三段式升级路径：
  1. QKE 平台升级 v3.3.0 → v3.4.0（保持 k8s v1.27.10 不变）；
  2. 通过 QKE web 控制台升级 k8s：v1.27.10 → v1.29.10 → v1.31.2；
  3. 手动执行 kk 命令升级 k8s：v1.31.2 → v1.33.4。
- **理由**：
  - QKE v3.3.0 最高支持 k8s v1.27.10，无法直接升级更高 k8s 版本；
  - QKE v3.4.0 最高支持 k8s v1.31.2，且其控制台支持 1.27.10/1.29.10/1.31.2 三个版本；
  - kubekey 3.1.12（3.1.x 线最高 tag）支持到 k8s v1.33.4，可手动升级到该版本。
- **状态**：已确认（用户提出，作为项目既定思路）。

### D-005：第三阶段 kk 升级命令

- **日期**：2026-09-30
- **决策**：第三阶段在 master1、installer 目录内执行：
  ```bash
  ./kk upgrade -f config-sample.yaml --with-kubernetes 1.33.4 --skip-pull-images --skip-dependency-check
  ```
  升级前需清理 feature-gates（1.33 移除项）、升级 etcd 到 3.5.24、调整数据库字段。
- **理由**：`--skip-pull-images` 跳过预拉镜像（前提：目标镜像已推入私有仓库）；`--skip-dependency-check` 跳过 KubeSphere↔k8s 依赖矩阵检查（QKE 组合可能不在 kubekey 内置矩阵内）。
- **状态**：已确认（来源：qke-cli worklist + qke-artifacts 资源包）。

### D-006：中间版本说明（控制台路径 vs 资源包镜像）

- **日期**：2026-09-30
- **决策**：
  - 控制台升级路径 **1.27.10 → 1.29.10 → 1.31.2** 是 QKE 控制台提供的路径，在 kubekey 支持的 k8s 版本内，无问题；
  - qke-artifacts 资源包的控制面镜像 **v1.29.15 / v1.32.8 / v1.33.4** 是 **kubekey 3.1.12 升级阶段**（1.31.2 → 1.33.4）所需的：kubekey 升级时逐 minor 版本进行，会拉取各中间版本镜像（这是 kubekey 本身的升级逻辑，与是否手动调用无关）；
  - 资源包已预下载 kubekey 升级过程中自动下载的各 k8s 版本所需文件（etcd、calicoctl、kube 二进制、helm 等），避免离线环境因文件下载故障而停顿。
- **理由**：QKE 3.4.0 原资源包 kubekey 为 3.1.7，不支持升级到 1.33.4；新资源包更换为 3.1.12 并补齐依赖。
- **状态**：已确认（用户提供，2026-09-30）。

### D-008：kubekey 版本事实与整体升级步骤

- **日期**：2026-09-30
- **决策（事实澄清）**：
  - **QKE v3.3.0 使用的 kubekey 版本为 3.1.0**；
  - **QKE v3.4.0 使用的 kubekey 版本为 3.1.7**；
  - **kubekey 3.1.7 不支持升级 k8s 到 v1.33.4**，因此**必须更换 QKE v3.4.0 的 qke-installer 包中的 kubekey，使其版本为 3.1.12**；
  - 基于以上考虑，才有制作和更新 QKE v3.4.0 qke-installer 包的动作。
- **整体升级步骤（3 步）**：
  1. **导入 QKE v3.4.0**（此工作由**青云专业人员**处理）；
  2. **更新离线环境中 QKE v3.4.0 的 qke-installer 文件包**（参考 `/workspace/qke-artifacts/` 中的步骤）；
  3. **执行具体的升级步骤**（三段式：平台升级 → 控制台升级 k8s → 手动 kk 升级）。
- **状态**：已确认（用户提供，2026-09-30）。
- **备注（已澄清）**：**测试环境**中用户**调整了 installer 包内的 kubekey 版本**——QKE v3.3.0 从 3.1.0 → **3.1.7**，QKE v3.4.0 从 3.1.7 → **3.1.12**，因此实测该实例升级前 kk 为 v3.1.7、升级后为 v3.1.12。**真实离线环境不同**：QKE v3.3.0 为 3.1.0、QKE v3.4.0 为 3.1.7（原始），需更新为 3.1.12。

### D-009：coredns 版本决定因素与升级条件

- **日期**：2026-09-30
- **决策（事实澄清）**：
  - **coredns 版本由 kubekey 版本决定**（**非 QKE**）；
  - **kk 升级时不会自动升级 coredns**（实测确认）；
  - **是否需升级 coredns 由 k8s 版本的要求决定**；若需升级，方案需补充相应内容（见 §6.1⑦）。
- **kubekey 对 k8s 1.33 的 coredns 配套版本**：**v1.12.0**（来源：kubekey components.md）；当前 QKE 3.3.0 实例为 1.9.2，实测升级后仍为 1.9.x。
- **调研结论（子 agent 调研 k8s v1.33.4 官方源码/文档，2026-09-30）**：k8s 1.33 **无 coredns 最低版本要求**，1.9.x 基本可用（监听 v1 EndpointSlice）；**v1.12.0 为官方配套版本，强烈建议升级**（非"必须"）。详见 [refs/k8s-1.33-coredns-compatibility-report.md](refs/k8s-1.33-coredns-compatibility-report.md)。
- **状态**：已确认（用户提供，2026-09-30）；是否需升级**已调研**（结论：非必须，强烈建议）。
